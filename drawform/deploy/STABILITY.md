# T-27 单进程串行稳定性检查

从源码根 `drawform/` 执行：

```sh
PYTHONPATH=src ../spike/.venv/bin/python -m drawform.eval.stability \
  --step /绝对路径/合成样件.step \
  --output /绝对路径/尚不存在的输出目录 \
  --iterations 1000
```

使用已有 Python 环境与系统 `ps`，不增加运行依赖。
同一个子进程、同一个调用线程连续执行既有 `render_part(..., with_questions=True)`。
外层进程只负责收集退出状态和生成摘要，不运行第二份几何引擎；没有线程池或进程池。

## 保留的证据

- `input.step`：本次样件的独立副本，避免测试期间原路径变化影响输入。
- `metadata.json`：样件 SHA-256、Python/平台/库版本、源码指纹及本次比对规则。
- `iterations.jsonl`：每轮开始和结束即时落盘，含进程/调用线程、耗时、RSS、原始与比对哈希。
- `iterations/0001/` 至 `iterations/1000/`：每轮的 DXF、SVG、PDF、JSON；图名固定为 `stability`。
- `worker-stderr.log`：Python 异常或原生崩溃栈。
- `summary.json`：实际次数、退出码、一致性结果、内存和耗时汇总。

输出目录必须尚不存在，检查器不会覆盖旧批次。
一旦出图失败、文件缺失或非元数据内容不同，就停止并保留现场，不自动重试。
原生崩溃时，摘要仍报告最后启动轮次与验证通过轮次，不把缺失轮次算成成功。
运行期间不要同时跑其他几何测试，也不要修改源码；结束时会再次核对输入和源码指纹。

## 原文件与内容比对分别报告

原始文件逐字节哈希始终保留。DXF/PDF 的创建元数据会变化，不能把原文件哈希不同直接说成几何不同。
当前检查器只在用于比对的内存副本中排除以下已核实字段，不改写任何产物：

| 文件 | 允许排除的内容 | 仍严格比较 |
|---|---|---|
| DXF | HEADER 中的 `$TDCREATE`、`$TDUPDATE`、`$FINGERPRINTGUID`、`$VERSIONGUID`；根字典 `EZDXF_META` 下创建/写入标记的时间部分 | 所有图元、尺寸值、文字、层、其他字段；ezdxf 版本标记仍比较 |
| PDF | trailer 所引用 Info 对象内的 `CreationDate`、`ModDate` 数字，等长替换以保留 xref 偏移 | 图面 stream、字体、其他对象及其字节 |
| SVG / JSON | 无 | 原始全部字节，不舍入浮点，不排序或删掉候选 |

元数据结构不符合已核验格式时会失败，不进行猜测性过滤。
单元测试包含反向样例：尺寸/坐标、其他文本或非 Info 对象内的日期变化必须被检出。

## 内存与耗时的范围

RSS 在每轮出图及文件比对后由系统 `ps` 采样。报告首轮、末轮、采样峰值、前后 100 轮均值和末段斜率。
这是整个工作进程的驻留内存，包含 OCCT、Python、绘图出口及检查器；不能仅凭 RSS 给某个库定泄漏责任。
采样峰值不等于渲染过程中瞬时峰值。检查器不强制垃圾回收，不预设“内存通过”阈值。

耗时覆盖单次 `render_part`，包括四种出口，文件哈希和 `ps` 开销不计入该字段。
p95 使用本次完整单次耗时样本的最近秩，不把各阶段的 p95 相加。

少量试跑可显式降低 `--iterations`。`status=completed` 只表示指定轮次执行齐全；
少于 1000 次时 `t27_repetitions_met` 始终为 false。

## 结论边界

1000 次串行结果不证明多线程/多 worker 安全。`concurrency_verified` 始终为 false。
测试仅覆盖指定合成样件及当前软件环境，不替代 30 件真实审图或已知缺陷修复。
正式交付仍需 P0.4 的现场条件和审核记录；不能据此跳过 T-28～T-30 的依赖。

> ⚠️ 真实件表现以「一次通过率」为准，见开发包 08 §三。
