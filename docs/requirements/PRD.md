## 1. 一句话目标

**输入一个 3D 模型（STEP），输出一张工程师可直接复核的 2D 工程图：视图布局、基准体系、尺寸、公差与形位公差、表面粗糙度、技术要求，全部由 AI 生成，人只做复核，复核结论可追溯。**

"做出来"的客观定义不是"图能看"，而是第 11 节三个指标同时达标。

---

## 2. 目标与成功标准

### 2.1 要解决的问题

机械设计工程师把 3D 模型转 2D 工程图时，视图生成、基准判断、尺寸与公差标注高度依赖人工；工程规范与历史经验分散在国标、企业标准和个人脑子里。结果是制图周期长、质量一致性差。

### 2.2 人机分工（产品的基本立场）

> **AI 完成标准化标注；工程师负责复核与复杂判断。**

这条分工不是退让，而是设计约束：AI 只被允许在**规则可支撑、条款可引用**的范围内自主决策；一旦置信不足或规则冲突，必须**主动转人工**，而不是硬编一个答案。系统必须能区分"AI 不知道"和"AI 知道但没有把握"。

### 2.3 成功标准（可量化）

| 编号 | 指标 | 定义 | P0 目标 |
|---|---|---|---|
| M1 | **尺寸漏标率** | 金标准尺寸集中未被标出的比例 | ≤ 8% |
| M2 | **尺寸错标率** | 标了但值错/类型错/位置错的比例 | ≤ 5% |
| M3 | **冗余标注率** | 多标、重复标、参考尺寸误标为主尺寸的比例 | ≤ 10% |
| M4 | **可审计率** | 输出标注中，能给出「置信度 + 命中条款号 + 生成依据」三项齐全的比例 | ≥ 95% |
| M5 | **主动转人工准确率** | 低置信样本被正确升级人工的比例（宁可转，不可编） | ≥ 90% |
| M6 | **单图端到端耗时** | STEP 进 → 可复核图出，P0 类零件 | ≤ 90 s |
| M7 | **人工复核工时下降** | 与纯手工制图对照 | ≥ 40% |

M1/M2/M3 必须**三分类同时看**——只报"准确率 95%"没有意义，因为它掩盖了漏标和错标的分布。

| 维度 | 结论 |

## 4. 首期范围与边界

### 4.1 功能范围：全链路四道工序

```
① 视图工序   → 视图方向优选、三视图/剖视/局部放大布局、隐藏线与中心线
② 基准工序   → 基准体系（A/B/C）选择、基准符号
③ 尺寸工序   → 尺寸方案生成（标哪些、标在哪、尺寸链）、线性/直径/半径/角度
④ 公差工序   → 尺寸公差（IT/ISO 286/ISO 2768）、形位公差 FCF、表面粗糙度、技术要求文本
```

### 4.2 零件类别分期（重要：首期不做全品类）

| 期 | 零件类别 | 理由 |
|---|---|---|
| **P0** | 回转体（轴、套、法兰、盘）+ 简单棱柱件（底板、支座、连接块） | 几何规则最确定、国标覆盖最全。**注：「约占机械图纸六成」为立项假设，无一手统计支撑，须用集团真实图纸包计数核实（PDM 可取，见 §数据源）（见 R10）** |
| P1 | 箱体、叉架、支架类 | 多基准、跨视图尺寸链，需要工序间回退机制 |
| P2 | 复杂曲面、薄壁、钣金 | 展开与成形公差，规则库覆盖薄弱 |

**P0 之外的类别，系统必须显式回答"超出首期能力范围"，不允许硬编。**

### 4.3 明确不做（边界）

- ❌ 不做参数化建模（不是 CAD 建模工具）
- ❌ 不做装配图与爆炸图（P2 之后另议）
- ❌ 不做 2D→3D 反向重建（Werk24/SanCo 的方向，与本目标相反）
- ❌ 不做 CAE/工艺路线生成
- ❌ 不承诺"替代工程师签字"——系统只生成待复核图纸，**永不输出"已批准"状态**
- ❌ 不承诺高保真 DWG（见第 10 节）

### 4.4 目标 CAD 环境与交付形态（2026-10-06 决策）

**主要覆盖 CATIA（三维）与 AutoCAD（二维）生态。**

| 项 | 决策 | 依据 |
|---|---|---|
| 交付形态 | **独立工具**，不做 CATIA/AutoCAD 插件 | 不依赖使用部门的 CAD 授权与 API；一套代码覆盖两类用户。插件形态列为二期候选 |
| 输入 | **STEP / IGES**（工程师从 CATIA 导出） | `.catpart` / `.catproduct` **OCCT 读不了**；直读需 CAA API 或商业 SDK |
| 输出 | **DXF + PDF 为验收项**；DWG **暂不硬性要求** | 保持许可证干净的纯 Python 栈（OCP LGPL + ezdxf MIT + TolForge Apache） |
| 输出架构 | `render_output` 必须做成**可插拔适配器**，DWG 位留空 | 后期可插 ACadSharp（MIT，C# sidecar）或商业 SDK，不阻塞主线 |

**由此产生的两个必须自研项**（原以为可复用，实测后确认不行）：

1. **SVG/PDF 预览渲染器必须自研** —— `ezdxf.addons.drawing` **不渲染 TOLERANCE 实体**，且 `⏥` 符号在自带字体下显示为空框。因此 DXF 交付层写真 TOLERANCE 实体，而 PDF/PNG 预览层必须自绘公差框格。
2. **DWG 写回放弃自研** —— LibreDWG 官方自陈写支持只到 r2004，R2010+ 部分对象读失败，且 GPL-3.0 只能子进程隔离。ODA File Converter 闭源且非会员仅限非商业用途，**当时按对外交付判定不可用**（该结论在集团自用定性下待法务复核，见 §4.4 末）。

**产品运行形态：网页端 + 集团内网服务端（2026-10-07 决策，同日修正定性）**

> ⚠️ 本段原写作「客户内网私有化服务端」。同日明确 **DrawForm 是集团内部使用的工具，不存在商业化与上线**，措辞与判据一起改过来。改的不只是名词：**没有客户就没有合同兜底，验收只能靠证据**；反过来，"仅限非商业用途"那类组件的许可结论可能要重开一次（见本节末）。

不做桌面 App。三条理由在自用场景下依然成立：

1. **图纸是集团资产，服务要在内网。** 内网放一台服务器、浏览器访问即可；发 exe 到几十台工程师电脑会带来分发与升级两个问题，而当前迭代节奏是一天一版，桌面分发会直接拖慢迭代。
2. **「转人工」要求服务端。** 产品核心形态是"知道在哪停下来问人"，而工程师的回答往往不是当场给 —— 可能隔天回来接着看。LangGraph `interrupt()` + `SqliteSaver` 的跨进程恢复已实测成立，这个能力只有在服务端才有意义；桌面 App 一关，问一半的问题就丢了。
3. **我们不需要 CAD 编辑器，所以浏览器最大的短板不存在。** 工程师最终一定回到 AutoCAD/CATIA 改图（PRD 明确不做参数化建模）。界面只做三件事：**看图、回答机器问出的问题、把集团现有的图框模板拖进来**。

**这个决定立刻顶上来一项工作**：浏览器不能可靠渲染 DXF（线宽、GB/T 字体、公差框格），所以 §4.4 自研项 1 的 **SVG/PDF 渲染器从"以后再说"变成排期最前**，它同时是 PRD 验收项「DXF + PDF」的前置。

**自用不等于没有边界（2026-10-07 新增，属当下的实际风险，不是以后的事）**：服务端骨架已经起来了，用的是 Flask 自带开发服务器 —— 单进程、无 TLS、**没有任何鉴权**。任何能连上那个端口的人都能让服务往服务器磁盘写文件。自用确实去掉了计费、多租户、对外 SLA 这些必要性，但**没有去掉这三问：谁能用、产物落在哪、磁盘涨到怎么办**。它们要在第一批工程师真正接入之前定下来，落点是《部署与运维》。

**ODA File Converter 的许可结论要重开一次**：原判定是「非会员仅限非商业用途，不能随私有化交付」。集团自用更接近非商业使用，该限制**可能不再构成障碍**，那样 DWG 读写这条路会重新打开。但"内部使用算不算商业用途"取决于集团与 ODA 的关系及分发范围，**属法务判断，不在工程侧自行认定**，此处只登记待决。

**可选补充形态**：若有部门要求"CATIA 里存一下图就自动出"，加一个**无界面的本地目录监听服务**（监控发布目录 → 推 STEP 给内核），不是桌面 App，不影响主形态。

**CATIA/AutoCAD 生态带来的额外要求**（已并入功能需求）：- 汽车与装备行业以 **GB/T + ISO 第一角投影**为主，涉外订单遇 **ASME Y14.5 第三角**；两套约定的**小数分隔符**（逗号 vs 点）、投影角标记、公差表达必须可切换 —— 开源数据集 `cadsy/cad-technical-drawings` 正好提供同一模型的双标准配对（ISO 65 张第一角 + 小数逗号，ASME 65 张第三角 + 小数点）
- AutoCAD 侧要求 DXF 图层规范（可见/隐藏/中心/尺寸/公差分层），便于工程师在 AutoCAD 里二次编辑
- CATIA 侧要求导出的 STEP 能被稳健读回（AP203/AP214 单位与装配结构差异需在 `import_step` 的诊断中暴露）

## 5. 核心闭环（一次完整交付）

```
工程师上传 STEP
   ↓
[工序①] 视图：HLR 投影 → 视图选型 → 排版防重叠 → 隐藏线/中心线
   ↓
[特征提取] 圆柱面/平面/孔系/沉孔/螺纹/圆角倒角 → 特征清单（几何事实源）
   ↓
[工序②] 基准：RAG 检索"该类零件基准惯例" → 规则引擎约束 → 选 A/B/C
   ↓
[工序③] 尺寸：基准体系 + 特征清单 → 尺寸方案（漏标/冗余在此判）
   ↓
[工序④] 公差：特征功能分类（配合面/安装面/自由面）→ IT 等级 → 偏差值 → FCF → 粗糙度
   ↓
[规则校验] 合法性校验（引用完整性 + 数学一致性 + 版面冲突）
   ↓
[置信判定] 低置信 / 规则冲突 → 转人工确认（可隔天续跑）
   ↓
[渲染交付] PDF + SVG + DXF（+ DWG 降级）
   ↓
[人工复核] 审图台逐项接受/修改/驳回
   ↓
[回写] 复核结论 → 任务上下文 + Bad Case 库（可追溯决策闭环）
```

**交付物**：一张可复核工程图（PDF/SVG/DXF）+ 一份标注清单 JSON（含每个标注的置信度、命中条款、生成依据）+ 一份决策轨迹（工序顺序、工具调用、转人工原因）。

### 6.1 两条 OCCT 硬坑（必须写进工程规范，否则一定重犯）

1. **不调 `HLRBRep_Algo.Hide()`，隐藏线恒为 0 条。** 精确 BRep HLR 的默认行为如此，多边形 HLR（`HLRBRep_PolyAlgo`）会给出隐藏线但是网格碎片级、不可用。
2. **必须在 `Update() → Hide()` 之后才读 V 和 H。** `Hide()` 之前读到的 `VCompound()` 是"未消隐"的全部轮廓 —— 会把隐藏线画成实线。

> 第 2 条是本项目实际踩到、靠浏览器渲染图才发现的 bug。参考实现 `dooosp/freecad-automation` 犯的正是同类错误（它把 projectEx 十元组的索引映射搞错，硬隐藏线被画成实线），**不要照抄它**。

## 7. 技术栈决策

### 7.1 几何层：纯 OCP（`cadquery-ocp`），**不引入 FreeCAD**

| | FreeCAD 方案 | **纯 OCP（采用）** |
|---|---|---|
| 磁盘 | +1.0 GB | 0（已在 venv） |
| GUI 依赖 | 页面级 `exportPageAsPdf/Svg` 在 `TechDrawGui`，依赖 `QGSPage`，必须开 GUI | 无 |
| 隐藏线 | `projectEx` 十元组 `[V,V1,VN,VO,VI,H,H1,HN,HO,HI]`，索引易错 | 已验证正确 |
| 可控性 | 受版本与 API 变动牵制 | 直接调 OCCT |
| 唯一损失 | — | 拿不到可编辑 `.FCStd` 与真 `DrawViewDimension` 对象 |

**决策依据**：交付物是 PDF/SVG/DXF，不需要可回编辑的 CAD 源文件。若二期使用部门要求 `.FCStd`，再以子进程方式挂 FreeCAD，不影响主架构。

## 11. 知识库与 RAG

### 11.1 语料现状（重要约束）

- ✅ 可获得：国标/行标文本、企业制图标准（PDF，含扫描件、双栏、公差表、图形符号）
- ⚠️ **改口（2026-10-07）**：原列「❌ 不可获得（二期依赖）：客户历史图纸库」。集团自用之下它不是不可获得，而是**最该先拿到的数据**——PDM 里的历史图纸由集团自己的工程师绘制，同时提供手工基线（工时、返工、驳回）与基准选择的事实依据。当前状态：**未接入，待明确取数渠道**。
- ❌ **查无开源**：中文机械/标准领域 RAG 语料与评测集（HF/ModelScope 与 `gh search` 命中 0）

### 11.2 因此必须自研的（占工作量约 70%）

1. **条款感知切分**：必须保留「标准号 + 章/条/款」结构，否则无法溯源（M4 依赖此项）
2. **公差表扁平化**：数值矩阵"一行一段落"，行列错位即语义致命
3. **图形符号规范化文本表示**：形位公差框格、粗糙度 Ra、基准字母 —— **OCR 会丢或错位，这是真难点，不是 OCR 精度问题**
4. **工程同义词归一**："配合面" ↔ 轴颈/孔表面
5. **标准间引用图谱跳转**：GB/T 1182 引 GB/T 1800 之类
6. **强制条款号引用 + 低置信拒答**

### 11.3 检索策略

稠密（Qwen3-Emb）+ 稀疏（Qdrant native sparse）双路召回 → Qdrant 内置 RRF 融合 → Qwen3-Rerank 精排。参考 RAGFlow 的融合 rerank 策略（**其许可证核实为 Apache-2.0，但它是独立应用且正在 Go 重写，不能当库嵌 → 只抄策略**）。

## 12. 评测体系

### 12.1 分层评测集

| 层 | 内容 | 来源 |
|---|---|---|
| 常规件 | P0 类零件，标准画法 | `cadsy/cad-technical-drawings`（Apache-2.0，65 STEP ↔ 130 张图 ISO+ASME 双 profile + 每个标注 bbox/text/type）+ ADSKAILab Zero-To-CAD-100k 程序化扩展 |
| 复杂件 | 多基准、跨视图尺寸链 | 资深工程师人工标金标准（30–50 例） |
| 对抗输入 | 缺失特征、非流形、超复杂曲面、图纸与模型不一致、单位错误 | 人工构造 |

**关键设计**：cadsy 这类"STEP ↔ 图纸 ↔ 标注三元组"数据意味着可以**自造无限、坐标系精确的 ground truth**，这是离线评测的地基，比任何 VLM benchmark 都贴合本项目的目标函数。

### 12.2 三层评分机制

| 层 | 手段 | 判什么 |
|---|---|---|
| 确定性 | pydantic `model_validate` + 几何量测断言（如 V4/V5） | 结构正确性、值正确性、漏标/错标/冗余三分类 |
| 规则判定 | 规则校验器（gdt-coach 骨架 + 自研规则） | 引用完整性、FCF 合法性、基准一致性 |
| LLM-as-a-Judge | promptfoo + DeepEval，**judge 用与生成端不同的模型** | 技术要求文本合理性等规则判不了的 |
| 人工抽检 | 工程师按分层抽样复核 | 校准前三层，防指标自欺 |

> ⚠️ 静态扫描分数不是生产验收结果。M1–M7 必须由真实评测集跑出，不能用"能出图"代替。
