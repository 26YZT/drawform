负责人：张岩（实现）／产品负责人（口径确认）

## 0. 三个已定的决定，和它们各自的后果

| # | 决定 | 后果（必须一起接受的） |
|---|---|---|
| 1 | **任何持令牌的人都能回写** | 回写权限不与身份绑定。系统只能记"自称是谁"，记不住"是不是他"。 |
| 2 | **改后图算生效版本** | 我们不再只是"出底稿的工具"，而是**生效图纸的产生点**。责任链从"线下签字"移到这里。 |
| 3 | **理由分类要改，作为集团口径** | 分类表升格为口径，需要版本号、生效日期、校准计划，否则一年后没人知道它凭什么这么分。 |

### 0.1 决定 1 + 2 合起来的那句话

> **任何拿到访问令牌的人，都能产出一张生效图纸。**

共享令牌是单机口令，可复制、不轮换、不区分人。这组合在"底稿工具"阶段可以接受，
在"生效版本产生点"阶段是**放行前必须补的洞**。三条缓解，按代价从低到高：

- **M1（本次一起做）**：生效版本必须带**非空复核人姓名**，与父版本哈希一起进审计日志；
  页面上每次生效动作都显式回显"谁、什么时候、基于哪一版"。
- **M2（本次一起做）**：令牌改成**每人一份**（`DRAWFORM_TOKENS` 支持逗号分隔的多令牌，
  令牌→姓名映射写进配置），审计里记令牌指纹而不是明文。这样"持令牌者"至少可追溯到席位。
- **M3（推广前必须）**：挂到集团反向代理 + SSO 之后，姓名从"自报"变成"断言"。
  这条不做，第 3 阶段（常态期）不进入。

M1/M2 是这次设计的一部分；M3 写进《部署与运维》的放行条件。

## 1. 目的与非目的

**目的**：工程师在 CAD 里改完底稿之后，改动要能回来，并且回来之后系统能说出
"你删了 1 条、改了 2 个数值、基准从 A 换到 B"——**当场让他确认机器读懂了**。
这批差异是唯一能告诉我们"机器该学什么"的数据。

**非目的（明确不做）**：
- 不做在线 CAD 编辑器（不在浏览器里画图）；
- 不做 PDM 直连（试点期导出一个包，由 PDM 管理员入库；直连等接口规范）；
- 不做版本冲突合并（一份底稿只接受一份改后图；要再改就基于改后图再出一版）；
- 不做 DWG 回写（这台机器读不了 DWG，见《部署与运维》第六节）。

## 2. 术语

- **机器底稿（draft）**：`render_part` 产出的 `part.dxf`，永不覆盖。它是版本链的第 0 版。
- **生效版本（effective）**：工程师回写的 `amended-N.dxf`。**头版（最新那一版）就是那张图的交付物**。
- **版本链**：`draft(sha) → amended-1(sha) → amended-2(sha)`，每跳带审计记录，
  每跳的差异只与**直接父版**比。
- **冻结**：这张图的审计里出现过 A 组（数值级）理由之后，`accepted`（"直接用"）这一格永久不可填。

## 3. 存储与数据模型

**2026-10-09 补充：任务表本身也落盘了**（`<work>/jobs.jsonl`，append-only）。
生效版本上线之前，"重启丢任务表"只意味着重新上传一个 STEP；之后它意味着
**把人改出来、已经生效的那几版图弄丢**（文件在盘上，索引没了，`/effective`、`/diff`、
交付包全部指向不存在的东西）。所以任务表现在是那份 JSONL 的缓存：
目录被清理掉的任务不装回来；重启时还没跑完的任务记成 `crashed` 并写明"请重新提交"。
实测：重启后 `/effective` 与重启前上传的那一份字节一致，交付包仍含整条链。

> 更正：这笔改动的提交 `1fe9dbb` 的说明文字贴错了（写成了上一笔"逐项差异"的文案）。
> 内容无误，只是记录错了 —— 记在这里，不改写历史。

```
<work>/<job_id>/
    part.dxf          机器底稿，只读，永远是第 0 版
    part.json         假设清单等结构化事实
    amended-1.dxf     第 1 版生效图
    amended-2.dxf     第 2 版生效图（链只追加，不覆盖）
<work>/reviews.jsonl  审计：结论 + 理由 + 人名 + 时间 + 版本哈希 + 版号
```

审计记录新增字段（向后兼容，旧行缺字段按空处理）：

```json
{"at":"…","job":"…","decision":"amended","reviewer":"设计-甲","version":2,
 "reasons":["datum_choice"],
 "draft_sha":"…","effective_sha":"…","diff":{"removed":1,"added":0,"value_changed":2,
 "datum_changed":1,"symbol_wrong":0,"style":0},"token_hint":"3f2a"}
```

`draft_sha` 是**防错传的锚**：回写时带上"我改的是哪一版"的哈希，服务端与**当前头版**比；
不一致说明他改的是旧版或别人的图 → 拒绝（409），而不是收下两份对不上的东西。
写进审计行的这个哈希由**服务端算**，不转述客户端自报的值 —— 否则整条链可以被人随手改写。

## 4. 接口

| 方法/路径 | 作用 | 关键约束 |
|---|---|---|
| `POST /jobs/<id>/amended` | 上传改后 DXF，登记为**下一个**生效版本 | multipart；只收 ASCII DXF；≤64 MB；`reviewer` 非空；基线哈希必须等于当前头版；**不覆盖底稿、不覆盖任何一版** |
| `GET /jobs/<id>/effective` | 下载**当前**生效版本 | 稳定 URL，PDM 与"接着改下一版"都认它；没有则 404 |
| `GET /jobs/<id>/files/amended-N` | 下载链上任意一版 | kind 只认任务记录里已登记的 |
| `GET /jobs/<id>/diff` | **头版 vs 机器底稿**的差异摘要 + 版号 | 只读，可重复算；答"机器一共要改几处" |
| `GET /review/stats` | 结论分布 + **理由分布 + 差异动作分布** | 试点复盘的唯一出口 |
| `GET /jobs/<id>/package` | 导出交付包（**整条生效链** + 底稿 + JSON + 审计行） | 给 PDM 管理员用，试点期人工上传 |
| `POST /jobs/<id>/review` | 记一条复核结论 | `accepted` 在**冻结**的图上直接 409 |

`POST /jobs/<id>/amended` 成功后**自动落一条 `amended` 结论**，不需要人再点一次按钮——
否则会出现"传了生效图但统计里没这条采用记录"的漏。

## 5. 差异对比：先粗后细，分两级

### P0（本次做）—— 实体与数值层，全部用现成件

复用 `eval/intake.py`（数实体、读块内尺寸）、`eval/dwg_roundtrip.py`（比显示值）、
`eval/ingest.py`（外部 DXF → `Drawing`）。产出六类动作：

| 动作 | 判据 | 挂的理由 |
|---|---|---|
| `removed` | 底稿有、生效版本没有的 DIMENSION 显示值 | `missing_dimension`（反向）或 `extra_dimension` |
| `added` | 生效版本多出来的 DIMENSION | `missing_dimension` |
| `value_changed` | 同一位置（锚点距离 < 2 mm）两侧都有，显示值不同 | `wrong_value` |
| `datum_changed` | 基准代号字母变了 | `datum_choice` |
| `symbol_changed` | ⌀ / ⌴ / ↧ / R / ×数量 前缀变了 | `wrong_symbol` 或 `wrong_count` |
| `geometry_touched` | 轮廓/中心线/剖面线被增删（说明他动了视图） | `view_choice` |

`value_changed` 的**位置配对**是这一步唯一的新算法：按尺寸锚点（尺寸线中点）就近配对，
阈值 2 mm。配不上的退回 `removed`+`added`，**不猜**。

### P1（等真实数据再决定）—— 语义层

把生效版本上每条尺寸反指回几何特征（"这条 42 是 ⌀40 那个孔的深度"）。
这要求外部图 → 特征的映射，而**外部图没有我们的 feature_id**。
这件事的判据要靠集团真图校准，现在做等于照想象的图猜 —— 所以放 P1，不做。

## 6. 理由分类 v2（集团试点口径）

**版本**：`DF-RC-0.1`，生效日 2026-01-30（文档日历），由产品负责人确认，
**待试点真实驳回分布校准**。保留这一行溯源，是为了将来企标到手时知道哪些格是拟的、哪些是抄的。

四组十四条，**A 组是阻断级**：出现即说明图纸有错，不是风格分歧。

| 组 | id | 中文 | 判据（复核人勾选时看到的解释文案） |
|---|---|---|---|
| **A 数值正确性** | `wrong_value` | 尺寸数值与模型不符 | 这个数本身错了，照它加工就废件 |
| | `wrong_count` | 重复特征数量或并组错 | 4× 写成 3×、该并组的没并 |
| | `wrong_symbol` | 符号或用词错 | ⌀/⌴/↧/R/Sink 用错，或该写直径写了半径 |
| **B 标注取舍** | `missing_dimension` | 漏标：该标的没标 | 加工/检验缺依据 |
| | `extra_dimension` | 多标：冗余或不该标 | 制造时无用，检验时扯皮 |
| | `datum_choice` | 基准选错或该换 | 数值对但起点不是设计基准 |
| | `tolerance_missing` | 该给专门公差没给 | 配作/装配尺寸只落在一般公差里 |
| | `chain_open` | 尺寸链留空的那一环不对 | 该留的没留、不该留的留了 |
| **C 表达与图面** | `view_choice` | 视图数量或剖切位置不对 | 表达不出结构，或多画视图 |
| | `unreadable_sheet` | 图面读不出 | 字压线、字压字、标注重叠 |
| | `style_violation` | 线型/字高/箭头不合规范 | 尺寸线、点画线、箭头比例 |
| **D 数据与范围** | `title_block_fields` | 标题栏字段不对 | 图号、材料、比例、版本、重量 |
| | `not_applicable_part` | 这类零件本就不该由工具做 | 超出 P0 范围 |
| | `other_needs_text` | 以上都不是（必须写 note） | 兜底项，note 必填，防止自由文本变成垃圾桶 |

与 v1 的差异：新增 A 组三条（**v1 把"标错了"和"标漏了"混在一起，而这两者的严重度差一个量级**）、
新增 `chain_open`、`other_needs_text`（兜底但强制写清楚）、每条配一句判据文案直接显示给复核人。

## 7. 三个未决的答复（产品负责人 2026-10-09 拍板，均已实现）

1. **一份底稿允许多份生效版本**。链 `draft → amended-1 → amended-2 …`，每版只与直接父版比，
   头版是交付物；旧版全部留在盘上与交付包里。
2. 生效版本**不自动回推 PDM**，仍走导出包由人上传。（这条没变。）
3. **A 组出现即冻结这张图**：审计里出现过 `wrong_value` / `wrong_symbol` / `wrong_count`
   —— 不管来自改后图比对还是复核人勾的驳回理由 —— `accepted` 一律 409。
   冻结只拦"直接用"，不拦「改后采用」与「驳回」，且**不会因为后来又操作一次而自行解除**。

第 3 条留一句反面话：冻结是**流程上的止血**，不是正确性证明。它拦不住"没人回写、
也没人驳回"的静默采用 —— 那要靠试点期的实际使用密度，代码做不到更多。

## 8. 测试策略

- **TDD**：每条判据一个测试。硬判据至少四条：不覆盖底稿、`draft_sha` 不匹配就拒、
  回写自动落 `amended` 结论、A 组理由不能与 `accepted` 同时出现（若 §7.3 采纳）。
- **变异测试**：逐条拆判据，要求当场变红。上一轮有两条变异存活，暴露的是"负向断言在
  本来就动不了的几何上空转"——这次每个"不该发生"的断言都要配一个"同样几何下它会发生"的前提。
- **对照组**：diff 判据先在**自家图 vs 自家图**上量（应报 0 差异），再拿
  公开样本里改过的图量。脏尺子误杀好规则这事本项目栽过一次。
- **浏览器端到端**：真传一份改后 DXF，看差异摘要是否与他实际改动一致。
  上一轮"接受记录里混进驳回理由"就是只有点一遍才发现的。
- **回归**：`pytest tests/ -q` 当前基线 480 passed + 1 xfail，只许升不许降。

## 10. 验收标准（可测）

1. 传一份改过的 DXF 上来，系统回显的差异**与改动事实一致**（人工核对 3 例）；
2. 底稿文件字节级不变（哈希前后一致）；
3. `GET /review/stats` 能区分"数值错"与"漏标"两类，且 A 组单独成项；
4. 每一次生效动作都能在审计里查到：谁、什么时候、基于哪一版（哈希）、改了什么；
5. 传错文件（别人的图 / 旧版本）被拒，且拒绝理由说清楚；
6. 全库回归不低于 480 passed，且新增判据各有变异验证记录。

## 11. 实现回记（同日）

实现过程中改了两处设计，都是被验证逼的，不是顺手改的：

- **校验顺序**：先验"能不能读"，再验"是不是这一版"。反过来的话，传上来一个 DWG 会先撞上
  版本不匹配，报出"请基于刚下载的那一版改"——一个误导人的理由。
- **配对规则**：设计里写的是"按锚点距离就近配对"。变异测试（把排序换成按序号）存活，
  查下来是**这条规则本身定得不好**：删掉一条尺寸、另一条挪近一点，纯按距离会读成
  "80 被改成了 7"。改成**先认显示值相同、再认距离**，并补
  `test_pairing_prefers_the_same_label_over_the_nearest_anchor`。11 条变异至此全被抓。

浏览器端到端结果：删掉 `4×⌀5` 那一条后上传，页面回显「已生效。机器读到的改动：removed 1」，
`/review/stats` 给出 `decisions.amended=1`、`diff.removed=1`、`reasons.extra_dimension=1`、
`blocking=0`。**前端有个 bug 是只有点一遍才发现的**：submit 事件里 `e.target.files` 是
undefined（`e.target` 是 form 不是文件框），点"上传为生效版本"毫无反应，而 18 条接口与页面
测试全绿。已加一条正向断言钉住。

## 12. 冻结与版本链落地回记（2026-10-09）

§7.1 与 §7.3 两条同日实现，新增 15 条测试（441 → **456 passed + 1 xfailed**），
9 条变异全被抓。实现里有一处不是照设计写的：

- **版本号分配与基线校验必须在一把锁里**。设计里写的是"上传 → 校验 → 存文件"三步，
  真按三步写，两个席位同时回写会都算出"下一版是 1"，后写的把前一张生效图覆盖掉，
  而两条审计行都写着"我已生效"。收进 `JobQueue.put_version()` 一次加锁做完，
  对外返回 `Version(number, path, parent)`。
- **审计行里的父版哈希由服务端算**，不转述客户端传来的 `draft_sha`。
  客户端那个值只用来做校验，写进台账的是事实。

浏览器端到端（`part_0004`，任务 `8b2b3867c89a`，令牌席位「设计-甲」）：

| 步骤 | 页面/接口回显 |
|---|---|
| 上传第 1 版（把首条 `80` 改成 `99.5`） | 「已生效（第 1 版）。相对上一版的改动：value_changed 1｜含数值级错误，这张图已冻结：不能标「直接用」…」 |
| 点「直接用」 | 「这张图已有数值级错误记录，不能标「直接用」。请改好后回传生效版本，或选「驳回」说明问题」（409） |
| 点「下载第 1 版接着改」 | 落盘文件与上传那份 `cmp` 一致；URL 是 `/jobs/<id>/effective`，带 Authorization 头 |
| 在第 1 版上删一条尺寸后上传 | 「已生效（第 2 版）。相对上一版的改动：removed 1」——**没背上第 1 版那个错号** |
| 再点「直接用」 | 仍 409：冻结不因后续操作解除 |
| 拿机器底稿的哈希再传一次 | 409「你上传的改后图对不上当前生效版本（第 2 版），请重新下载最新的那一版再改」 |
| `GET /jobs/<id>/diff` | `{"diff":{"removed":1,"value_changed":1},"version":2}` |
| `GET /jobs/<id>/package` | `8b2b3867c89a.dxf` + `amended-1.dxf` + `amended-2.dxf` + `review.jsonl` |
| `GET /review/stats` | `blocking=1`、`decisions.amended=2`、`reasons={wrong_value:1, extra_dimension:1}` |

审计链两行的哈希接得上：第 1 版 `draft_sha=7be7b95c`（机器底稿）/ `effective_sha=2606296f`，
第 2 版 `draft_sha=2606296f` / `effective_sha=ae0f4833`。

一个已知缺口，没偷偷补：**任务列表点不回去**。页面刷新后 `jobId` 清空，而 `<li>` 没有点击
处理器，所以"重新打开页面继续改第 3 版"这条路只能靠重新出图。`show()` 已经改成
优先用 `/effective` 当基线，等列表可点时不用再动回写逻辑。
