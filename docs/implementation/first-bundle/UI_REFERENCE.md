## 首段能力说明

页面明确写出简单板件、垫圈/圆片与单视图图纸边界；不提供模型供应商选择，不宣传通用 LLM 或任意图纸重建。文件不超过 20 MiB，上传请求只含 `file`，不附带文字框内容。PDF/DXF 的输入预览仅展示后端返回的已鉴权 PNG，禁止注入源 SVG/PDF/HTML。

会话新增 `analyzing` 与 `needs_clarification`：前者轮询，后者停下等待人填写。补充请求携带 `basis_sha256`、`revision` 和 `Idempotency-Key`；原图冲突或 blocked 不开放提交，readonly 不发送覆盖答案。事实中的 `evidence.type=user_answer` 单独列为用户补充。恢复会话从持久化结果重新呈现原图、事实、问题与参数。

访问令牌复用同源 `sessionStorage.dfToken`，不写入 URL、日志、下载文件名或业务请求体。采用模型仍只确认参数，不能标为工程审图通过。

第三段修改入口只接收服务端 `editable_spec` 中已有的长宽厚、内外径、孔 XY/直径；只提交实际改动的白名单 ops，不增删或重排孔。请求携父 STEP SHA、父 spec SHA、最近分配版本号与幂等键。修改成功后用新的 session URL 查看并轮询，旧版下载、采用和二维 Job 关系保持。源图派生的修改明确标为设计变体，变化列表来自服务端，原始证据仍保留。

无孔、双孔文字示例使用 T1 约定的完整有限语法，由用户主动填入；初始文字框为空。示例不引入默认制造尺寸，也不参与图纸上传请求。

文字会话存在 `analysis` 时，完整显示顶层 `session.text` 及 `source_sha256`；仅在顶层文字缺失时兼容旧 `source.text`。全文通过 `textContent` 和保留换行样式准确显示，不使用规范化文字的 offset 截取原文。`analysis.normalized_text` 与其 SHA 单独折叠展示；`text_span` 证据显示后端片段、`span_basis=normalized_text` 对应范围及来源 SHA。原始读出事实、用户补充答案和模型设计变体的服务端修改列表独立呈现，用户补充证据不会冒充原文片段。

文字澄清沿用数值/选择 typed form，缺值保持空白；支持 `holes.0.x_mm/y_mm/diameter_mm`、孔坐标原点、孔形式与毫米选择。负数及零保持数字类型，由后端按参数语义校验。新 basis/revision 更新问题时清除旧表单，不自动将旧答案应用到新问题。新增主动填写的“缺厚度示例”，句子为“做一块长100毫米、宽60毫米的板，中间开一个直径20毫米的通孔”；页面只填文字，实际追问由后端产生。

阶梯轴参数卡和修改表单均采用显式第三类型分支，四字段的来源、问题与服务端变化以中文呈现；修改只发已有数值的 `set_parameter`，不新增段数或孔。`shaft_solid=solid` 必须由原始事实或用户显式确认，不从缺少孔描述推断。缺第2段长度示例仅主动填入“实心阶梯轴，第1段直径40毫米长30毫米，第2段直径20毫米”，实际仅问 L2 由后端确认。未知 kind 显示规格不支持，不默认解释成板件或垫圈。既有模型查看器、采用/STEP、历史/409和二维绑定逻辑保持。
