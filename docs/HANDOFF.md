## 0. 这是什么产品（一句话 + 三条推论）

**汽绘 DrawForm：输入一个 3D 模型（STEP），自动产出一张 GB/T 口径的零件图（DXF/SVG/PDF），
图能直接在 CAD 里接着改，且任何不合格的都拒绝出图。**

- 这是**能力目标，不是差异化目标**。成功定义是"AI 真能把一张工程图做出来"，不与他人比定位。
- 这是**集团内部自用工具**，没有商业化、没有上线日期、不给外部用户。别按 SaaS 的思路加东西。
- 范围只有 **P0 两类零件**：回转体 + 简单棱柱件。别的路径（装配图、钣金展开、焊接图）不在范围内。
- 值班理念：**"停下来问人"是产品的一部分，不是失败。** 现在做不到，是因为"问"的通道还没建，
  不是因为该悄悄替人决定。

## 3. 六条纪律（这个项目的分数能骗人，这六条是防骗的）

1. **先重现，再引用。** 报告任何数字前跑对应的命令。本项目真实踩过：把 `test_svg.py` 的 14 条
   记到 `test_pdf.py` 头上、把基线日期写成 10-09（实际 10-11）、提交说明写"24 条新测试"实际 23 条。
2. **写生产代码之前先有失败的测试**，并看着它因"功能缺失"而失败（不是因拼写错误而崩）。
3. **变异测试要区分"断言失败"与"崩溃"，并且要认出等价变异体。** 改了实现而测试全绿，
   如果那段代码本来就到不了，那是**死代码，删掉它**，不是补一条测试。
4. **负向断言必须先证明正向本来会发生。** 空转的判据比没有判据更危险 —— 它给所有人"已经守着"的错觉。
   本项目真实踩过两次：一次探针没传 `datum_marks`，符号 polyline 数为 0，于是"引出线穿尺寸线 0 处"
   是假的；一次语料级 text/line 判据同样空转。**新增任何一层交付物，就让 65 件语料跑批穿过那一层。**
5. **新检查器先找对照组。** 自家图 vs 自家图必须报 0；然后拿 1909 张公开图量出"正常值是多少"，
   否则你不知道自己拦下的是问题还是特征。曾有一条判据差点拦掉 4/65 个好零件。
6. **UI/页面改动要在真浏览器里点一遍**（上传→轮询→看差异表），type check 证明不了功能正确。

## 5. 你现在接手的状态（每条都有出处，引用前跑一遍）

- 判分口径是 **F2**（不是 F1）：漏标按 β²=4 倍代价，因为漏一个尺寸比多标一个贵得多。
  基线 **F2 76.9% / recall 77.9% / precision 72.9% / 漏标 141 / 多标 185 / 落位 99.8% / 门拦 3-of-65**。
  ⚠️ 引用时必须带上"语料是 65 件 **cadsy 自动生成**图纸，不是人画的"。
- 回归 **501 passed + 1 xfail(strict)**（xfail 是 GEO-019，见下）。
- **`output/drawing.py` 是唯一几何源**，SVG/PDF/DXF 都只是序列化器。改几何只改这一处，
  否则三个出口会各自漂移 —— 这是本项目最重要的架构约束。
- 尺寸方案是一层**代数**：`Sized` = 一个方程，`Chain` = 一个方程对 n 个未知量，`_pinned` 是不动点。
  合法性由 `dimensioning/constraints.py` 的 linter 管（欠定/超定/封闭链/无基准/无公差归属）。
- 交付门 `delivery.py`：**不过关就不出图，一次报齐不短路**，检查器自己抛异常按不通过处理。
  稳定 id：`invalid_solid` / `unclassified_faces` / `illegal_plan` / `unplaced_dimensions` / `sheet_overflow`。
- 闭环已在：复核三态（接受/改后采用/驳回）、**数值级错误即冻结该图**（A 组理由出现后 `accepted` 一律 409）、
  改后图回写 = **生效版本链**（`amended-1 → amended-2`，差异只与直接父版比，逐项明细进审计）、
  交付包 zip、`work/jobs.jsonl` 任务表落盘。
- 在册未修：**GEO-019**（阶梯通孔中间加粗段被当沉孔，发出编造的 `⌴⌀70 ↧90`；两种改法都被自己的
  数据推翻，会误杀真实有深度的构型，现挂 strict xfail 等第三例）、**GEO-008 残留**（盲孔开口判据
  在带圆角台阶上会误判）、`jobs.jsonl` 只增不减。
