## 实现与证据

| 规则 | 代码与边界 |
|---|---|
| 1 | pilot.report 同时报 first_pass 与 end_to_end_direct；拒绝出图、程序异常、排队、运行、未审单列，零分母为 null |
| 2 | 答案审计不算人工改图；回传本身不算采用。首次明确接受前有实际变更的人工回传计改后采用；原样逐字节回传不冒充手工改图。首次退回保留 |
| 3 | corrections 命令保存人工净改动与累计改动依据，绑定图纸 SHA-256；答案版本不能填成人工版本；记录缺失/过期单列，不填零 |
| 4 | rejection_reason_rates 使用退回件数作分母，多原因去重后分别计数 |
| 5 | 同审核人同批次五题起报；秒选排除只有一个候选的题，阈值仍为 5 秒含等号；缺耗时单列 |
| 6–9 | operations 的 check/watch 按 60/300 秒采样，进程与任务事件每秒观察；磁盘边界、三次 HTTP 失败、30 分钟/4 小时提醒及一次恢复通知有测试。本地事件日志无外发行为 |
| 10–11 | 删除队列按数量清理的实现和参数；retention 的 close/evidence/logs 只登记结束或生成待确认清单，不删除数据；未登记结束不能凭文件时间推算过期 |
| 12 | operations backup 必填台账，外置台账与全部业务文件进入同一份校验清单；恢复校验 STEP 关联指纹。备份保留 7 日份/4 周份只输出复核清单，升级前备份与完整归档另列保护 |

处置登记只追加运维说明，不取消仍未恢复问题的提醒，也不改变图纸/审计/冻结状态。

## 本机真实 HTTPS 与恢复演练

[live-final/verification.json](../../drawform/out/p0-policy-a-20261014/live-final/verification.json)：

- 原业务文件哈希不变；外置台账恢复后逐字节相同，并核验登记 STEP 指纹。
- 新 HTTPS 服务读回 4 个任务、26 个接口文件，TLSv1.3，一个应用 worker，冻结任务仍拒绝直接采用。
- 真实停止服务后检测到进程退出；第三次 HTTP 失败采样告警；重启后两项各通知恢复一次，不重复发恢复事件。
- 三次失败的采样时间由验证脚本推进，没有等待三个真实分钟，不把本结果称为实测停机 SLA。
- 演练服务均由脚本停止；未部署公司定时器，未发外部消息。

这些是合成样件的本机技术验证，不是 30 件真实件成绩或制图审核结论。
