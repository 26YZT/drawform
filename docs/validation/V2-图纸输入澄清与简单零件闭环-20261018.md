# 首包 v2：图纸输入、关键澄清与简单零件闭环

日期：2026-10-18。用户授权继续开发。上一段原型与文字带孔板基线保持，当前增量把真实图纸文件接入同一建模/STEP/出图链。本文描述本机技术验证；整个首包v2仍有后续工作。

## 可以体验的新增功能

| 输入 | 当前能力 | 信息不完整时 |
|---|---|---|
| DXF | 读取实际矩形轮廓、圆孔、原生单位/尺寸；支持0–16个显式贯通圆孔和同心圆盘/垫圈 | 追问单位、厚度、贯通性质，保留实体handle和图层出处 |
| PDF / PNG / JPEG | 本机Vision识字，根据明确的长、宽、厚、外径、内径及孔位等角色标注重建有限简单零件 | 关键标签缺失时追问；不把像素距离变成制造尺寸 |
| 文字 | 保持原中心通孔板语法，新增明确外径/内径/厚度的垫圈，以及实心圆盘 | 缺尺寸、未消费特征或不支持要求直接说明，不无依据填值 |

页面分开展示原图事实与用户补充，可查看原图预览和来源证据。用户补充绑定图纸SHA、问题版本和请求编号，旧依据拒绝，重复提交不重复构建。生成后旋转真实保存STEP的网格、核对参数和孔位、下载STEP，再确认采用并生成DXF/PDF/SVG。模型采用不代表工程审图accepted。

PDF/图片这一段是**明确角色标注的有限重建**，不是任意照片、多视图或手绘草图理解。没有外部视觉/文字模型调用，没有工程数据外发。DXF使用真实几何；栅格输入不以图形大小猜尺寸。

## 集成架构与代码

1. `workbench/drawing_intake.py`读取原生DXF，或调用`runtimes/drawing_bridge/drawing_ocr.swift`的Vision/PDFKit本地OCR；输出事实、问题和预览，不能直接采用模型或创建出图任务。PDF/图片所有非空识字文本另有逐片段消费记录；同一行未解释要求、其他页的备注、低置信未解释文本均不能静默忽略，须带原文/页码/位置阻断。仅明确图号、页码、比例等有限元数据可放行。
2. `workbench/drawing_workflow.py`负责原文件不可变SHA、分析快照、关键问题、版本绑定澄清和SQLite事务；原`inputs`四列结构保持，新图纸记录/澄清receipt另表扩展。
3. `workbench/simple_spec.py`定义schema2纯数据规格。板件孔XY相对板中心，统一毫米；校验有限正数、最多16孔、孔边界/重合/相切及内外径。客户端不能提交任意代码或磁盘路径。
4. `runtimes/cadgen_bridge/simple.py`在独立cadgen/build123d/OCP7.9进程生成并保存STEP；`workbench/inspect_simple.py`使用原DrawForm OCP8独立冷读，核对唯一有效闭合实体、外廓、体积、孔数/直径/位置/贯通和材料/空气点。原`plate.py`及依赖锁不改。
5. `workbench/modeling.py`与`api.py`保持原采用和唯一JobQueue；把确切保存STEP交给既有`pipeline`及唯一图形源，四种图件由原链输出。
6. `workbench/page.py`增加图纸切换、实际上传、来源及澄清界面，保留真实3D预览和下载。新会话完整清空旧2D状态，已有绑定任务可以恢复。

协议详见[DRAWING_CONTRACT](../implementation/first-bundle/DRAWING_CONTRACT.md)。OCR编译缓存为可再生的`drawform/out/drawing-native`，与本次证据目录分开；需本机macOS/Xcode命令行工具；本批在macOS验证，其他平台尚未验证。

## 当前边界与后续

- 支持矩形板、同心圆盘/垫圈及有限显式Z向通孔。已覆盖的盲孔、螺纹、沉孔、凸台、筋板、自由轮廓、多视图、公差/配合等实体或特征词会拒绝；PDF/图片的未解释OCR文本会阻断。OCR未识别的视觉特征仍需核对，原生DXF的任意自由备注不宣称完整语义理解。
- 暂不开阶梯轴：既有2D方案有肩面位置覆盖缺口，原生3D成功不能认领工程图完整。后续须先修肩面尺寸及其独立验收。
- 生成2D仍可能带设计基准、公差等审图问题；本批不代替用户回答工程意图，没有实际CAD应用打开/打印、工程师审图或加工验证。
- 外部模型provider、任意图纸理解、多轮特征编辑及完整legacy发布journal仍待后续。整个首包v2尚未完成；本批完成用户指定的图纸输入真实闭环子集。
