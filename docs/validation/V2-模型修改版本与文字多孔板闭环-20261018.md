# 首包v2：模型修改版本与文字多孔板真实闭环

日期：2026-10-18。用户授权“继续推进并完善”。本轮完成N10的本地受控参数修改/模型历史子集，以及完整文字无孔/显式坐标多孔板输入；全部沿用已有native STEP、独立OCP8检查和唯一2D出图链。

## 可以体验的变化

- 已生成模型可直接修改已有长、宽、厚、内外径及矩形板既有孔的XY/直径；只提交实际变化。内径0按已有圆盘规格校验，矩形板孔列表本段不增删或重排。
- 每次修改生成独立新模型版本，显示父版、修改前后值和版本列表。新版本须重新核对采用，随后产生自己的STEP和2D Job；旧版模型/图纸保持。
- 图纸派生修改明确标为设计变体，原图提取事实保持；修改值单列，不伪装成复现原图。
- 可切回任意保留版本，恢复该版本自己的模型与图纸；版本号由服务端事务分配，失败/中断版本保留，不按剩余文件重号。
- 文字新增明确无孔板、以板中心为原点的编号XY通孔板，最多16孔。源文字归档和SHA绑定保持。缺信息仍明确拒绝，不猜对称/均布/距边，不声称完整任意自然语言理解。
- 文件缺失/改变会显示产物不可用，阻止下载、采用、修改和新出图；父版的STEP、预览或检查文件损坏也会阻止子版继续使用其来源。

可用文字例：

> 矩形板，长120毫米，宽80毫米，厚8毫米。以板中心为原点，两个通孔。孔1：X=-25，Y=5，直径8毫米；孔2：X=25，Y=-5，直径12毫米。

> 矩形板，长100毫米，宽60毫米，厚8毫米，无孔。

## 集成与权威关系

- `workbench/text_simple.py`：完整有限文字→现有schema2 Spec；原中心通孔板解析器及垫圈/圆盘语法保持，`simple_spec.py`按明确矩形板类型接入新解析。
- `workbench/revisions.py`：追加`model_revisions`表，唯一约束保护父请求收据和根模型族版本号。父STEP/Spec SHA及最近已分配版本号均须匹配；事务内记录新session、父子关系、差异和收据，事务后才排入native构建。
- `modeling.py`：新旧规格统一为可编辑Spec；每次新构建仍原生保存STEP并双运行时冷读。逐层校验原始输入及祖先四产物，发布前/后和下载/采用继续核对。GET的`artifact_integrity`是保存产物完整性状态，不代表每次GET都重新做几何冷读。
- `drawing_workflow.py`：派生模型复用原输入预览，仍校验席位、原始输入SHA及预览SHA；原图事实不改。澄清事务读取原始记录，避免把派生展示字段写成权威数据。
- `api.py`：增加revisions/history；仅新修改接口严格解码嵌套JSON，重复键直接422。未知op/字段、表达式、重复修改、非有限数值、孔越界/相交等拒绝。
- `page.py`：差量编辑、冲突草稿保留、显式重新比较依据、版本切换、服务端差异、损坏阻断。历史缓存随选中版本状态/Job/完整性变化更新；迟到响应不覆盖新的选中版本。

接口及语义见[REVISION_CONTRACT](../implementation/first-bundle/REVISION_CONTRACT.md)。SQLite是模型关系/版本分配权威，`revision.json`是可阅读来源副本。这里没有统一项目HEAD；“采用”确认所选模型版本可用于出图，不自动替换其他版，也不等于工程审图accepted。模型版本与旧审图台DXF修改版本分别管理。
