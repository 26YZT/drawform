## 等价几何反例

对用户提供的NIST CTC01中 `bore--0.0-63.5085-d5.0-0`，保持原模型、直径、深度、方向及有限轴向范围不变；仅沿同一孔轴线换取相距10 mm的轴上点。`Bore.axis_point` 的源码契约本来就允许沿轴任取。

| 项 | 原表示 | 等价表示 |
|---|---|---|
| 轴线上一点XYZ，mm | 约(0,63.50850269,5) | 约(8.66025404,58.50850269,5) |
| 轴线垂距/有限段两端 | 相同 | 相同，比较误差0 |
| 轴上点是否在同一有限段内 | 是 | 是 |
| 方案Y定位值，mm | 288.5085026919324 | 283.5085026919324 |

方案Y值改变5 mm，虽然轴线和有限段几何没有变化。原因是当前 `_perpendicular_indices` 用分量绝对值小于0.5挑坐标，仍把斜轴上非零方向分量的任取坐标当作定位依据。材料边界参考修复的是默认外廓基准，不能定义孔轴的工程参考点或截面，也不能消除这类参考语义问题。

见[原反例](../../drawform/out/p0-oblique-reference-audit-20261015/axis-point-invariance.json)及[从当前源码重新提取特征后复核](../../drawform/out/p0-oblique-reference-audit-20261015/fresh-current-verification.json)。首次复核脚本把JSON列表与Python元组直接比较而失败，修正检查器表示后得到同一结果；不是新的产品崩溃。原始STEP SHA-256保持。

检查该柱面真实拓扑：两个边界为与其他柱面相交的B样条曲线，另两边邻接平面与孔轴平行。当前未取得可直接当成孔口的相邻平面或端圈截面，见[拓扑](../../drawform/out/p0-oblique-reference-audit-20261015/actual-rim-topology.json)、[相邻平面检查](../../drawform/out/p0-oblique-reference-audit-20261015/adjacent-reference-plane-candidates.json)及[端圈检查](../../drawform/out/p0-oblique-reference-audit-20261015/rim-reference-section-candidates.json)。不能把轴向范围的两端或中点直接命名为工程孔口，也不声称该模型不存在任何可用工程基准。
