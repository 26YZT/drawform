## 1. 它在解决什么问题（第一性拆解）

一张零件图的工作是**消掉"三维模型"与"可被制造并验收的零件"之间的自由度**。
拆开只有五件事：

| 工序 | 内容 | 信息在 STEP 里吗 | 现状 |
|---|---|---|---|
| ① 表达 | 用哪些视图、要不要剖 | **在**（几何本身决定） | ✅ 已实现 |
| ② 尺寸 | 标哪些、数值多少、怎么并组 | 数值在，**选哪些不在** | 🟡 数值全对，选择是策略占位 |
| ③ 精度 | 每个量允许差多少 | **不在** | 🟡 未注公差可查，专门公差为零 |
| ④ 基准 | 从哪个面量起 | **不在** | 🟡 默认外廓占位；可选真实基准面，斜孔参考另在图前确认 |
| ⑤ 其余要求 | 粗糙度/螺纹/技术要求 | **不在** | 🟡 数表齐，产出零 |

**结论：产品的难点全部集中在②③⑤的"没有参考答案就无法判断对错"那一侧。**
①已经做到不需要人管。所以本项目把"评测靶子"排在"继续加能力"之前 —— 这是路线，不是偏好。

## 3. 已实现（每条给证据入口）

**几何与出图**
- STEP → 三视图 + 全剖（剖切位置**由调用方给**）、GB/T 线型线宽、中心线、剖面线、视图名、剖切符号。
- 尺寸作为**原生 DIMENSION 实体**落到 DXF（工程师能在 CAD 里接着改，不是死图）：`tests/test_output_dxf.py`。
- 自研 SVG / PDF 渲染器，与 DXF 共用 `output/drawing.py` 一份几何：`test_every_gated_part_also_renders_to_svg_and_pdf`。
- 图框 + 最小标准标题栏（右下角、按 GB/T 10609.1 排布）。**STEP 里没有的格子（图样名称、材料、签字人）刻意留空**：`output/titleblock.py`。

**判断与守门**
- 尺寸方案合法性 linter（欠定/超定/封闭链/无基准/无公差归属）：`dimensioning/constraints.py`。
- 交付门 `delivery.py`：**不过关就不出图**，一次报齐不短路，检查器自身抛异常按不通过处理。稳定 id：`invalid_solid` / `unclassified_faces` / `illegal_plan` / `unplaced_dimensions` / `sheet_overflow`。
- 图面互斥检测 + 避让：字压字（47 → 0）、字被线穿（668 → 262）、基准代号沿自己的棱滑开（183 → 155）。检测与避让**共用同一份判据**：`output/collide.py`。

**度量与靶子**
- 非对称计分 **F2**（漏标按 β²=4 倍代价），去重口径，`shortfall` 只报告不计分：`eval/score.py`。
- 外部 DXF 体检 `eval/intake.py`、外部图读入 `eval/ingest.py`、DWG 往返判定 `eval/dwg_roundtrip.py`、改后图差异 `eval/amend_diff.py`。**每条判据都配了对照组**（自家图 vs 自家图必须报 0）。

**闭环（这一周新加的）**
- 复核：接受 / 改后采用 / 驳回，驳回必填理由分类（DF-RC-0.1 十四条，四组），append-only `reviews.jsonl` 活得比任务记录久。
- **数值级错误即冻结这张图**：A 组理由一旦出现，`accepted` 一律 409；只按任务算、只拦"直接用"、不自行解除。
- **改后图回写 = 生效版本**，可接力多版（`amended-1 → amended-2`），版本号与基线校验同锁分配；差异只与**直接父版**比；**逐项明细**（哪一条、从几改成几、图上位置）进审计行。
- 交付包 zip：整条生效链 + 机器底稿 + JSON + 审计行。
- 多令牌席位（`名字=令牌`）+ 令牌指纹进审计，不记明文。
- 问答层 `knowledge.py`：**只回答这张图算得出的事实**，词表之外一律显式拒答。
- 任务表落盘 `work/jobs.jsonl`：重启后已出图任务与生效链都能查回来。

## 4. 未实现（按"卡在哪"分，不按重要程度分）

### 卡数据（拿到集团真图纸才能做，写代码替代不了）
1. **实际工程基准判断**。闭合真实平面候选已可选择，但默认外廓占位和工程参考仍须人确认。历史全库漏标 141 条里 **87 条（62%）集中在线性尺寸池**，就是这个。
2. **"该标哪些尺寸"**。现在的对照物是 cadsy **自动生成**的图纸，不是人画的 —— 分数一直在跟机器习惯对齐。
3. **手工工时基线**。KR 里"替代多少制图劳动"目前**无法量化**，只能从 PDM/出图记录取。
4. **`leader/line` 的共线豁免边界**。GB/T 1182 允许基准代号与尺寸线对齐共线，而我们的判据把共线重叠算成相交；剩下 155 处里有多少是"其实合规"，要真图定边界。
5. **斜面/口袋特征**。斜孔投影成椭圆，找不到那个半径的圆 → 35 条直径发不出去；没有圆视图时 ⌀ 该标在哪，是画法决定。

### 卡决定（要人拍板，不是要时间）
6. **公差框格**：⚠️ **注意这里文档与代码不一致** —— `rules/notation.py:parse_fcf` 只是**解析器**（拿 NIST 真实框格验到 97.3%），且**只被 `eval/corpus.py` 用来读对照语料**；`output/` 里**没有任何框格渲染器**。要渲染，先要有人决定"专门公差由谁给"（见第 7 条）。
7. **专门公差的输入通道**。设计意图不在 STEP 里，正解是**让复核人当场填**（填了才有框格、才有依据、才进审计），这个入口目前不存在。
8. **禁止采用的硬清单**（安全件/关键件一律不许"直接用"）。代码给不出，是流程决定。
9. **签字生效归属**。现在 `reviewer` 是自报姓名，SSO 之前它不是身份凭证。

### 卡人/卡环境
10. **没有任何机械制图审核的人看过一张图**。所有分数都是跟合成参照对齐的。
11. **DWG 出口从未真机验证**。本机只能读 ASCII DXF；验证包在 `tools/dwg_verify/`，要在装 CAD 的机器上跑一次。
12. **正式部署验收**。本机Gunicorn/HTTPS已验证；现场生产访问和实际证书信任条件未验收。

DRAWFORM_TOKEN='设计-甲=tokA,工艺-乙=tokB'   # 不设就拒绝启动

## 8. 排期的判据（写给下一个改这里的人）

1. **尺子歪着的时候先修尺子，再往下做能力。** 每一项"分数大涨"先问是不是口径造成的失真。
2. **新增一层交付物，就要让真实语料跑批穿过那一层。** 只给那层写单元测试等于没测（本项目"指标量的是没画到图上的数据结构"已复发 6 次）。
3. **负向断言必须先证明正向本来会发生。** 空转的判据比没有判据更危险 —— 它给所有人一个"已经守着"的错觉。
4. **数表不许凭记忆填。** 两份独立来源逐格核对，标准留空的格子就留空。
5. **能拿到任何一份真实矢量图就先拿。** 它未必对口，但能把一条"不敢用"的规则变成"可以用"。
